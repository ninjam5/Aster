# AGENTS.md

This file provides guidance to agents when working with code in this repository.

## Commands

```powershell
python main.py                          # Start Aster (headless CLI)
pytest tests/test_migration.py -v       # Run migration test suite (53 tests, mocked LLM, no LLM server needed)
pytest tests/ -v                        # Run full test suite (~900 tests)
pytest tests/test_playbooks.py -v       # Run UI playbooks + UWP suite
pytest tests/test_console_logger.py -v  # Run console debug logger tests
pytest tests/ -v -k "test_name"         # Run single test by name
```

## Critical Non-Obvious Patterns

- **No virtual environments** — all packages installed globally via `python -m pip install <pkg>`. Never create venvs.
- **PolyStrata (Strata engine) is the single engine** at `http://localhost:8080/v1` (Qwen 3.6 35B-A3B MoE, 128k ctx, q8_0 KV, mmproj vision on the GPU; Faster-Whisper stays OFF the GPU — voice notes use the CPU instance, while voice calls load CUDA Whisper `small.en`) — no `llama-cpp-python`, no llama.cpp / llama-server, no Ollama. One unified server serves text, vision, tool calls, Discord, and sentry. Start via `qwen3.6_polystrata_start.bat` or `Start-all.bat`.
- **Voice calls run via direct local WebSocket audio (`WS /api/voice/ws` on `:8000` via `LocalWebSocketVoiceBridge`)**: LiveKit Agents SDK (`ManualWebRTCBridge`) has `devmode=False` (no supervisor/worker multi-GB process fork) and is benched by default (`daemons.webrtc_bridge: disabled`, `voice.transport: local_ws`) for future mobile app use.
- **Cloud voice via Deepgram Flux (editable in `self_config.yaml`)**: Voice calls are configured to use cloud Deepgram Flux STT (`flux-general-en` on `/v2/listen` via `deepgram.STTv2`) and Flux TTS (`flux-colin-en` British Jarvis voice on `/v2/speak` via the in-repo [`deepgram_tts.py`](deepgram_tts.py)). `LocalWebSocketVoiceBridge` manages its own standalone `aiohttp.ClientSession` so Deepgram STT/TTS runs in-process with zero LiveKit worker dependency. Can be swapped back to on-device audio at any time by editing `self_config.yaml` (`voice.stt_provider: local` / `voice.tts_provider: local` for `small.en` Faster-Whisper + Kokoro TTS). Resolution is **fail-closed** — no `deepgram.api_key` in `secrets.yaml` ⇒ automatically stays local. Telegram voice notes and CLI are always local. Spec: `engine_testing/qa/voice-cloud-swap.md`.
- **Native OpenAI tool calling** — `ADMIN_TOOLS` (full JSON-Schema dicts) is sent as the `tools` param on every `/v1/chat/completions` POST; PolyStrata returns a structured `tool_calls` array, and tool results go back as `role:"tool"` messages with `tool_call_id`. The legacy XML-in-text path (`_polyfill_tool_calls`, `_legacy_xml_parse`) was **removed in the Qwen 3.6 swap (2026-09-27)**.
- **Adding a tool requires 3 edits**: (1) schema dict in `ADMIN_TOOLS` list (~line 446 in `core/brain.py`), (2) `elif` branch in `_execute_tool_impl()`, (3) import at top of [`core/brain.py`](core/brain.py).
- **Two separate brain contexts**: Admin (71 tools, 15-round loop) vs Discord (4 tools: `forward_to_owner`, `save_personal_fact`, `remember_pronoun`, `get_current_track`, 4-round loop), fully independent histories.
- **Outbound Discord relay is archived**: `send_discord_message` bot relay is commented out in `ADMIN_TOOLS` in favor of Desktop GUI Automation (Option B) via `open_application('discord')` and playbooks. Inbound Discord DM listening remains active via `tools/discord_listener.py`.
- **Two-Tier UI Playbooks (`tools/playbooks.py`, `Aster_Vault/playbooks/*.json`)**: 18 pre-seeded JSON playbooks across Desktop tier (13 apps: chrome, discord, instagram, stremio, steam, epic_games, riot_client, league_of_legends, spotify, telegram, vscode, file_explorer, windows_shell) and Web tier (5 domains: web_youtube, web_google, web_github, web_reddit, web_gmail) with bidirectional alias resolution and Gemini 3.8 Flash self-healing.
- **Extended GUI primitives & Foveated Vision**: `mouse_hover` (triggers hover action bars without clicking), `drag_and_drop` (continuous mouseDown->move->mouseUp for sliders/files/playlists), `click_at` (raw coordinate click escape hatch), and `zoom_and_read` (foveated vision: takes a 1:1 uncompressed patch from native desktop buffer for fine print/small icons, costing only ~120 tokens). Multi-monitor display calibration is planned as `Aster-Tune`.
- **GUI automation & latency optimizations**: `press_key` for keyboard keys (Enter/Tab/Esc), NOT `smart_click`. Clicking the word "Enter" found by OCR is a known past bug. `type_text` supports `press_enter: bool` (default False) to press Enter immediately after pasting, and blocks typing if Aster's own Telegram control chat is foreground or if called unfocused at turn start. `smart_type` accepts both `submit` and `press_enter` to click, paste, and press Enter in a single round. `open_application` restores and brings existing matching windows to the foreground before launching duplicates, and supports Windows Store UWP app launching. Multi-tool GUI calls in a single round (`_extra_calls`) execute sequentially with automatic abort-on-failure and attach only the final screenshot.
- **In-loop screenshot pruning & KV-prefix preservation**: `_prune_in_turn_screenshots()` tombstones older GUI action screenshots (`[Previous screen archived]`) and strips duplicate `[UI Playbook: ...]` blocks inside the active tool loop so `mmproj` only encodes 1 screenshot per round; `purge_media_cache()` archives remaining images to `Aster_Vault/images/` at turn end. Internal vision calls (`_qwen_vision_locate`, `_qwen_vision_locate_boxes`, `look_at_screen`, `look_through_webcam`, `re_examine_image`, `verify_action_result`) prepend `messages[0]` and pass `tools=ADMIN_TOOLS` so they never evict PolyStrata's ~16.4k-token KV prefix cache, and `SCREENSHOT_MAX_WIDTH` defaults to `1280`.
- **Console Debug Logging (`tools/console_logger.py`)**: Gated by `runtime.debug: true` (or `debug: true`). Automatically tees stdout/stderr to date-stamped files in `Aster_Vault/console-logs/` with ANSI color code stripping and thread-safe writes.
- **No `<image>` marker injection** — the chat template (`E:\Models\qwen36_chat_template.jinja`, froggeric v22.5) places vision tokens itself. The Gemma-era marker injection was removed in the Qwen swap; do not re-add it.
- **Base64 purge** — `purge_media_cache()` strips base64 from history after each turn to prevent VRAM bloat; images are archived to `Aster_Vault/images/` with tombstones.
- **Credentials live in `secrets.yaml`** (gitignored, read via `config._secret()`) — never in `config.py` or `self_config.yaml` (the latter is exposed verbatim to the LLM via `get_my_config`).
- **Docs duty** — update root [`CLAUDE.md`](CLAUDE.md) after behavior changes; `summary.md` is a dated baseline updated on architectural shifts. Additional instructions live in `.github/instructions/` (`summary-workflow.instructions.md`, `read-docs-before-code.instructions.md`, `python-global-packages.instructions.md`).
- **Cleanup backlog** — [`improvements.md`](improvements.md) is the running dead-code / stale-doc audit (unused symbols, dead config flags, orphaned files, doc drift). Before deleting code or refreshing docs, check it first; add findings there rather than scattering them.
- **Disabled/archived code**: FastAPI dashboard (commented out in `main.py`), Sentry daemon auto-start (commented out), `tools/gui.py` (not imported), `send_discord_message` (commented out in `ADMIN_TOOLS`). The archived YOLO blocks in `tools/vision.py` and the Gemma native-audio path (`input_audio`) were **deleted in the Qwen swap**; PyTesseract OCR and OmniParser v2 / YOLOv8 active locator tracks (along with `USE_PIXEL_FALLBACK` and `ICON_CAPTIONER`) were stripped in favor of Direct Qwen 3.6 Vision Grounding; the Florence-2 captioner reservation was removed; `tools/web.py` does not exist (research lives in `tools/rag.py`). The entire emotion recognition and ambient audio subsystem was removed in commit `f65d3b1`.
- **Automation flags are default-OFF** — `USE_DOM_MOTOR` (DOM-first motor: `tools/dom.py`), `USE_LAYA_KERNEL` (System-1/Laya kernel: `core/system1.py`). `smart_click` gained a `confirm_send` param for the web send gate (auto-approved on explicit user commands like "tell/send/submit"). Stage plan + QA gates: `engine_testing/qa/`. **`browse_web`** (live web reading via an Aster-owned real Chrome/Edge) is a separate tool, always on unless `automation.web_browse: false`; with `automation.human_search: true` (set on this install) site+query lands on the site's home page and the model drives its own search bar. **The owner's real browser profile can NEVER be driven** (Chrome ≥136 port block on the default dir + v20 app-bound cookies; copies/junctions get the cookies PURGED — never attempt); `use_real_profile: true` fails loudly with the `login_once.py` alternative.
